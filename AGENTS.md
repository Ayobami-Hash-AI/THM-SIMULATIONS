# Repository working instructions

The owner has authorized updates to this repository for every TryHackMe simulation and associated screenshot they share with the assistant. Treat each new simulation update as an instruction to update the relevant case without asking for the same authorization again.

- Inspect the existing case and repository before editing; preserve unrelated work.
- Use simulations/<category>/<case>/README.md and screenshots/ with descriptive sequential filenames.
- Write professional first-person summaries for the analyst's demonstrated work. Do not present assistant-prepared queries as searches the analyst executed.
- Document alert details, evidence, timeline, queries and actual results, reasoning, disposition, proposed versus completed response actions, limitations, and lessons learned.
- Publish available evidence promptly and mark incomplete investigations as under investigation. Never invent verdicts, decoded content, screenshots, results, or completed actions.
- Review images before uploading. Redact real personal information and secrets; preserve relevant simulation artifacts.
- Embed screenshots with relative paths and useful captions. Maintain the root case index.
- After publishing, verify the branch, report, and screenshot references and give the owner a concise link.
- This workflow is triggered by evidence shared with the assistant. It does not provide background access to TryHackMe or automatically observe activity outside the conversation.
